## 왜 "챕터 = 셰이더 하나"가 아닌가

25개를 하나씩 훑으면 25번 감탄하고 아무것도 안 남습니다. 이 셋은 **같은 문제에
대한 25가지 답**이라, 배울 게 있는 곳은 개별 셰이더가 아니라 **답이 갈리는
지점**입니다. 그래서 챕터를 축으로 잘랐습니다.

| 챕터 | 축 | 갈리는 지점 |
| ---: | --- | --- |
| 0 | 조망 | 수면에 붙는 19개를 같은 무대에 세우고, 축 다섯 개를 예고 |
| 1 | 파도 | 정점을 무엇으로 미는가 — 사인 / 겹친 사인 / 게르스트너 / 노이즈 텍스처 / 안 밈 |
| 2 | 법선 | 반짝임을 어디서 얻는가 — 안 고침 / 유한차분 / 해석적 접선 / 법선맵 |
| 3 | 깊이 | 수심을 어떻게 아는가 — 안 읽음 / 임계값 / Beer's law / 교차 포말 |
| 4 | 굴절 | 수면 아래를 어떻게 가져오는가 — 화면 오프셋 / flow map / 전반사 |
| 5 | 포말 | 경계선을 어떻게 그리는가 — 하드코딩 원 / SubViewport 마스크 / 유니폼 / 전역 파라미터 |
| 6 | 슬롯·포팅 | 셰이더가 붙는 자리 네 곳, 그리고 4.7이 조용히 틀리게 만든 것들 |

챕터마다 슬라이더 한두 개가 **코드 칸의 숫자와 같이 움직입니다.** 값을 끌면
화면과 코드가 동시에 바뀌는 게 이 워크스루에서 제일 중요한 장치입니다.

## 무대

`water/water_stage.gd`가 칸(`WaterPlot`)을 나란히 세웁니다. 비교가 성립하려면
**물 말고 전부 같아야** 하므로, 칸마다 같은 형상을 짓습니다.

- **10도 기울어진 바닥** — 수심이 0.8에서 6까지 변합니다. 깊이 페이드와 Beer's law는
  이 그라디언트 위에서만 "깊이에 반응한다"가 눈에 보입니다.
- **수면을 뚫는 기둥 두 개 + 반쯤 잠긴 바위 두 개** — 교차 포말 확인용.
- **같은 궤도를 도는 주황 프로브** — `boat_position`(5번), `player_position`
  전역 파라미터(10번)를 매 프레임 먹입니다.
- **체커 바닥** — 굴절/왜곡이 얼마나 강한지 눈으로 재는 기준선.
- **위에서 내려보는 SubViewport 포말 마스크** — 1번이 요구하는 `foam_mask`.
- **태양은 카메라 반대 방위·고도 28도** — 원본 프로젝트와 같은 값입니다. 1번의
  `pow(NdotH, 324)`짜리 좁은 스펙큘러는 해의 반사 경로가 화면 안에 들어와야 보입니다.

칸 배치는 시점에 맞춰 통째로 회전합니다(`WaterStage.frame`). 그래야 나란히 놓은
두 칸이 언제나 정면으로 서고, 앞뒤로 밀려 크기가 달라지지 않습니다. 카메라 거리는
내용물 모서리를 카메라 좌표로 옮겨 놓고 직접 풉니다 — 내려다볼수록 가까운 줄이
튀어나와서, 눈대중 배수로는 스텝마다 프레임이 어긋납니다.

## 스크린샷으로 걸러낸 것들

세 가지는 "말은 맞는데 화면에 안 보이는" 스텝이라 도중에 바꾸거나 뺐습니다.
전부 오토투어 PNG를 실제로 열어 보고 잡은 것입니다.

**8번(Toon Water)을 깊이 예시에서 뺐습니다.** 8번은 `transparent = false`라
깊이 버퍼에 자기 자신이 이미 찍혀 있고, 그래서 바닥까지의 거리가 아니라 거의 0을
돌려받습니다. 원본 프로젝트의 `docs/previews/08_toon_water.jpg`가 온통 흰 것도
같은 이유입니다. 수심 그라디언트를 보여주려면 투명하게 그리는 셰이더여야 해서
**17번**으로 바꿨습니다.

**3번(Realistic Water)을 굴절 예시에서 뺐습니다.** 3번도 화면을 읽지만 가져온
색에 물색을 곱한 뒤 깊이만큼 다시 물색으로 섞기 때문에, 조금만 깊어져도 굴절한
그림이 통째로 잠깁니다. 굴절이 눈에 보이는 건 **16번**이라 그쪽을 예시로 쓰고,
3번은 "왜 안 보이는가"를 설명하는 스텝으로 돌렸습니다.

**법선맵에 `source_color`를 다는 함정은 스텝으로 넣지 않았습니다.** 원본 README의
다섯 번째 발견인데, 이 프로젝트의 텍스처는 전부 코드 생성이라 임포트 단계의 sRGB
디코딩이 개입하지 않습니다. 나란히 놓고 확대해 봐도 차이가 나타나지 않아서,
보여줄 게 없는 스텝은 주장만 남는다고 판단했습니다.

## 재현한 포팅 버그

챕터 6의 뒤쪽 세 스텝은 **고치기 전 사본**을 왼쪽·오른쪽에 나란히 놓습니다.
셋 다 컴파일은 통과합니다 — 그게 이 함정들이 위험한 이유입니다.

| 파일 | 되돌린 것 | 화면에 나타나는 것 |
| --- | --- | --- |
| `bug_03_depth_3x.gdshader` | 3.x NDC 깊이 공식 + 클립공간 z | 포말이 수면 전체에 깔리고 굴절이 튄다 |
| `bug_07_repeat.gdshader` | 컬러 램프의 `repeat_disable` | 물 바깥이 램프 반대쪽 끝을 집어 허옇게 뜬다 |
| `bug_03_pow.gdshader` | 포말 항의 `max(…, 0.0)` | 얕은 물가만 빼고 수면이 전부 하얘진다 |
