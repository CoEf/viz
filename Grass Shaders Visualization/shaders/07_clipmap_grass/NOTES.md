## 핵심 아이디어

잎 하나가 자기 위치에 대해 아는 것은 **하이트맵 UV 하나뿐**이다. 지형 노멀, 색 노이즈,
바람, 바람 어둡기가 전부 그 한 좌표에서 나온다. 그래서 잎들끼리 통신하지 않아도
들판 전체가 하나로 움직인다.

거리 LOD는 `COLOR.a` 에 4x4 정렬 디더를 걸어 처리한다. 잎이 통째로 팝하는 대신
픽셀 단위로 녹아 사라지고, 불투명 패스에 남아 있으므로 정렬 비용이 없다.

08번(파티클 프로세스 셰이더)과 짝으로 설계됐다. 이 프로젝트에서는 07은 MultiMesh로,
08은 실제 GPUParticles3D로 돌려서 **같은 그리기 셰이더의 배치 방식 차이**를 볼 수 있게 했다.

## 4.7 변환 내역

| 원본 (4.1) | 4.7 | 이유 |
|---|---|---|
| `mix(0, ..., k)` | `mix(0.0, ..., k)` | int 리터럴 |
| `clamp(x, 0, 1)`, `remap(..., 1, 0)` | `0.0 / 1.0` | int 리터럴 |
| `vec4(VERTEX, 1)` | `vec4(VERTEX, 1.0)` | int 리터럴 |
| `heightmap_normals : hint_normal` | 힌트 제거 | **아래 참고** |

`hint_normal`을 뺀 이유가 중요하다. 이 셰이더는 노멀을 `rgba.xzy * 2 - 1` 로 **직접**
언팩하는데, `hint_normal`을 붙이면 Godot이 그 PNG를 RGTC 노멀맵으로 임포트하면서
채널을 재구성해버린다. 셰이더가 읽으려는 채널이 그 과정에서 뭉개진다.
→ 이 텍스처는 데이터 텍스처로 다뤄야 하고, `.import`에서 `detect_3d/compress_to=0`,
`compress/mode=0` 이어야 한다 (이 프로젝트가 그렇게 설정해 뒀다).

## 이 프로젝트에서 추가한 것

`scripts/clipmap_fade.gd` - `fadeout_envelope` 를 매 프레임 카메라-패치 거리에 맞춰
재중심화한다. 원본 세팅(클립맵 지형 위를 걷는 카메라)에서는 이 값이 고정이어도 되지만,
갤러리에서는 같은 패치를 3m에서도 60m에서도 보기 때문에 고정값이면
"완전 불투명" 아니면 "완전 소멸" 둘 중 하나가 된다. 즉 비교하려는 그 기능이 안 보인다.
**보이는 페이드는 진짜 셰이더가 하는 진짜 일이고, 창만 옮겨준 것이다.**

## 이 프로젝트에서 측정된 것

- **바람**: 1.5초 동안 화면의 13%. 바람이 `VERTEX.x` 오프셋 하나라서 휘는 게 아니라
  미끄러진다. 실제 인상은 `wind_darken` 이 만드는 어둡기 이동이 더 크다.
- **알파 처리가 반쪽이다.** 거리 페이드는 디더로 잘 처리하지만, 잎 실루엣 자체는
  여전히 `ALPHA_SCISSOR_THRESHOLD = 0.7` 을 통과해야 한다. 그래서 잎 텍스처에 밉맵이
  있으면 45m에서 점 몇 개만 남고 사라진다 (밉맵을 끄면 정상). 둘 다 챙겨야지
  한쪽만 디더로 만든다고 해결되지 않는다.

## 필요한 입력

- 잎 텍스처 (`blade_mask_1.png`) - rgb와 alpha 모두 사용
- 하이트맵 노멀 (`heightmap_normals.png`) - **커스텀 패킹**:
  `r=(nx+1)/2, g=(1-nz)/2, b=(ny+1)/2`. `tools/gen_assets.gd` 가 이 규약대로 생성한다
- 색 노이즈, 바람 노이즈
- 지면이 하이트맵과 같아야 한다 → `scripts/heightmap_terrain.gd` 가 같은 매핑
  (반 텍셀 오프셋 포함)으로 지면 메시를 다시 만든다
